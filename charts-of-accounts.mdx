## Chart of accounts

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/accountant/chart-of-accounts`

### Purpose and access

Maintain the tenant’s ledger accounts and their hierarchy.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The screen has account-type and System Accounts filters, name/code search, an account table, and create/edit dialogs. Fields include name, code, type, parent account, and description.

### Fields and displayed information


Displayed table columns: **#**, **Account Name**, **Account Code**, **Account Type**, **Parent Account Name**, **Description**, **Action**.

### Interaction sequence

Choose **New Account** → enter the name and type → optionally add code and description → choose **Save Account**. Success closes the dialog and refreshes the list. Click an account name or **Edit account details** to populate the edit dialog; **Update Account** sends name, code, description, and parent, but no type change. Selecting a parent encounters the request mismatch described below.

### States and rules

Blank names are rejected. Search also matches description and parent name. This screen does not expose a delete action; do not infer removal from account filtering.

**Implementation gap:** The form sends `parentId` when you select a parent, while the create/update DTOs accept `parentAccountId`. The API enables `forbidNonWhitelisted`, so a nonempty parent selection is rejected as an unknown property. Saving with no parent omits `parentId`. Treat parent assignment as unfinished until the request contract is corrected.

### പ്രവർത്തനക്രമം

അക്കൗണ്ട് സൃഷ്ടിക്കുക → പേരും തരവും parentഉം നൽകുക → സംരക്ഷിക്കുക → പുതുക്കും. നിലവിലെ അക്കൗണ്ടിൽ പേര്, കോഡ്, വിവരണം, parent എന്നിവ തിരുത്താം; edit request തരം മാറ്റുന്നില്ല.

### നിലകളും നിയമങ്ങളും

ശൂന്യപേര് നിരസിക്കുന്നു. വിവരണവും parent പേരും തിരച്ചിലിൽ ഉൾപ്പെടുന്നു. ഈ സ്ക്രീനിൽ delete action ഇല്ല; ഫിൽട്ടറിൽ കാണാത്തത് നീക്കിയതാണെന്ന് കരുതരുത്.

**Implementation gap:** Parent തിരഞ്ഞെടുക്കുമ്പോൾ form `parentId` അയയ്ക്കുന്നു; create/update DTOകൾ `parentAccountId` ആണ് സ്വീകരിക്കുന്നത്. APIയിൽ `forbidNonWhitelisted` ഉള്ളതിനാൽ parent നൽകിയ request unknown property ആയി നിരസിക്കുന്നു. Parent ഇല്ലാതെ save ചെയ്യുമ്പോൾ `parentId` ഒഴിവാക്കും. Request contract തിരുത്തുന്നതുവരെ parent assignment പൂർത്തിയായതായി കണക്കാക്കരുത്.
