## Mahallu setup wizard

Host: `admin.<ROOT_DOMAIN>` · Route: `/onboarding`

### Purpose and access

Create a Mahallu and its initial administrator through the guided setup.

Entry, public access, and redirect rules are described for this screen below.

### Screen layout

Mahallu Details collects name and location; Administrator Account collects identity/password for new users; completion shows the created Mahallu URL and dashboard action. Existing users reuse their account.

### Fields and displayed information

| --- | --- | --- | --- | --- |
| Mahallu Name | `onboarding-mahalle-name` | text | Yes | Your Mahall Name |


#### Fields and filters: Location picker

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |

| Administrator Name | `onboarding-fullname` | text | Yes | Enter your full name |
| Email Address | `onboarding-email` | email | Yes | Enter your email address (e.g. admin@example.com) |
| Onboarding password | `onboarding-password` | password | Yes | Create a secure password |
| Confirm Password | `onboarding-confirm-password` | password | Yes | Re-enter your password to confirm |

| Link | Target in source |

### Interaction sequence

Enter Mahallu name/location → Next → complete account details → Complete Setup & Create Mahallu → register if needed, then create tenant → completion → open admin dashboard. URL conflicts retry once with a numeric suffix.

### States and rules

Name is required to advance. New users need name/email, an eight-character password, and matching confirmation. Existing users with a tenant redirect to the admin root. Stored draft data is read on entry; the current wizard does not continuously save edits to the draft.

Explicit validation messages in the rendered forms:

- Please enter your Mahallu Name.
- Please provide your name and email address.
- Password must be at least 8 characters long.
- Passwords do not match.


The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

മഹല്ലിന്റെ പേര്/സ്ഥലം → Next → account വിവരങ്ങൾ → Complete Setup & Create Mahallu → ആവശ്യമെങ്കിൽ register ചെയ്ത് tenant സൃഷ്ടിക്കും → completion → admin dashboard തുറക്കുക. URL conflict ഉണ്ടെങ്കിൽ numeric suffix ഉപയോഗിച്ച് ഒരിക്കൽ വീണ്ടും ശ്രമിക്കും.

### നിലകളും നിയമങ്ങളും

മുന്നോട്ട് പോകാൻ പേര് വേണം. പുതിയ userന് പേര്/email, എട്ട് അക്ഷര password, പൊരുത്തപ്പെടുന്ന confirmation വേണം. Tenant ഉള്ള user admin rootലേക്ക് redirect ചെയ്യും. Entryയിൽ draft വായിക്കുന്നു; നിലവിലെ wizard ഓരോ മാറ്റവും draftൽ തുടർച്ചയായി സംരക്ഷിക്കുന്നില്ല.

Rendered formsലെ വ്യക്തമായ validation സന്ദേശങ്ങൾ:

- Please enter your Mahallu Name.
- Please provide your name and email address.
- Password must be at least 8 characters long.
- Passwords do not match.


Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
