## Collections

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/finance/collections`

### Purpose and access

Review incoming collections, receipts, category/fund allocation, and accounting posting status.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The page has search, operational-fund, posting-status, category, and collection-type filters. A selectable table provides receipt viewing, edit, individual delete, and bulk delete; the record link opens a separate entry screen.

### Fields and displayed information


Displayed table columns: **Date**, **Receipt #**, **Payer / Member**, **Category / Fund**, **Status**, **Method**, **Amount**, **Actions**.

### Interaction sequence

Choose Record Collection to open the entry screen → save the collection → return to the list. Open a receipt to print/share; Edit pre-fills its modal. Confirm individual deletion or select rows and confirm bulk deletion → refresh the table.

### States and rules

Posting status falls back to the presence of a journal entry when absent. Filters operate on the loaded records. Deletion is wired to backend operations; keep this distinct from the unfinished family bulk-removal action.

### പ്രവർത്തനക്രമം

Record Collection വഴി entry സ്ക്രീൻ തുറക്കുക → വരവ് സംരക്ഷിക്കുക → പട്ടികയിലേക്ക് മടങ്ങുക. രസീത് തുറന്ന് print/share ചെയ്യാം; Edit നിലവിലെ വിവരങ്ങൾ നിറയ്ക്കും. വ്യക്തിഗതമായോ കൂട്ടമായോ നീക്കൽ സ്ഥിരീകരിക്കുക → പട്ടിക പുതുക്കും.

### നിലകളും നിയമങ്ങളും

Posting status ഇല്ലെങ്കിൽ journal entry ഉണ്ടോ എന്നതിനെ ആശ്രയിക്കുന്നു. ഫിൽട്ടറുകൾ ലഭിച്ച രേഖകളിലാണ് പ്രവർത്തിക്കുന്നത്. നീക്കൽ backendലേക്ക് അയക്കുന്നു; പൂർത്തിയാകാത്ത കുടുംബ കൂട്ടനീക്കലുമായി ഇത് കലർത്തരുത്.
