## Billing usage

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/billing/usage`

### Purpose and access

Inspect the tenant resource-usage presentation.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

Plan limits and usage contains storage and resource cards for subdivisions, members, programmes/registers, users, messaging, and website views.

### Fields and displayed information


This screen has no editable fields or filters in its rendered components.


### Actions


| Control | Result | Component |
| --- | --- | --- |
| Refresh | Updates local UI state; persistence is described separately below. | `billing-usage.tsx` |
| Resources | No direct click handler; may be a menu trigger or linked control. See the sequence below. | `billing-usage.tsx` |
| Recalculate | Updates local UI state; persistence is described separately below. | `billing-usage.tsx` |



### Interaction sequence

Refresh or Recalculate → a timed loading indicator runs → the existing displayed figures remain. Resources has no connected click handler.

### States and rules

Used and limit figures are fixed component values. This screen does not measure storage, enforce quotas, or recalculate live usage.

### Implementation references

Paths below are relative to the application repository. This is source-reviewed behavior, not a recorded browser test.

- `apps/web/src/app/sites/admin/[tenant]/billing/usage/page.tsx`
- `apps/web/src/features/billing/billing-usage.tsx`

Data and access helpers: `apps/web/src/lib/session.ts`, `apps/web/src/lib/server-api.ts`, `apps/web/src/lib/tenants.ts`

### API behavior references

## Billing usage

### ഉദ്ദേശ്യവും പ്രവേശനവും

Tenant resource usage കാഴ്ച പരിശോധിക്കുക.

Account sessionഉം തിരഞ്ഞെടുത്ത മഹല്ലിൽ resolved membership contextഉം വേണം; APIയിലെ നിലവിലെ platform elevation pathഉം ഇതിൽപ്പെടും. ഓരോ പ്രവർത്തനത്തിന്റെയും permissions/features API പ്രത്യേകം പരിശോധിക്കുന്നു.

### സ്ക്രീൻ ക്രമം

Plan limits and usageൽ storage, പ്രദേശങ്ങൾ, അംഗങ്ങൾ, programmes/registers, users, messaging, website views കാർഡുകളുണ്ട്.

### ഫീൽഡുകളും പ്രദർശിപ്പിക്കുന്ന വിവരങ്ങളും

### പ്രവർത്തനക്രമം

Refresh/Recalculate → timer loading കാണും → നിലവിലെ കണക്കുകൾ തുടരുന്നു. Resourcesന് click handler ഇല്ല.

### നിലകളും നിയമങ്ങളും

Used/limit കണക്കുകൾ സ്ഥിരമായ component values ആണ്. Storage അളക്കലോ quota enforcementഓ live usage കണക്കാക്കലോ ഈ സ്ക്രീൻ നടത്തുന്നില്ല.
