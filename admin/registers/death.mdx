## Death register

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/registers/death`

### Purpose and access

Maintain the death register for this tenant using its own record fields.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The page presents a heading, record count, Add record, and a configured table. Add/edit opens a scrollable two-column dialog; long remarks span the width. Certificate controls appear beside eligible records.

### Fields and displayed information


Displayed table columns: **Deceased**, **Date of death**, **Place**.

#### Fields and filters: Page

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Deceased name | `deceasedName` | text | Yes | — |
| Father/guardian name | `fatherOrGuardianName` | text | Not marked | — |
| Gender | `gender` | select | Not marked | Male, Female, Other |
| Date of birth | `dateOfBirth` | date | Not marked | — |
| Date of death | `dateOfDeath` | date | Yes | — |
| Place of death | `placeOfDeath` | text | Not marked | — |
| Cause of death | `causeOfDeath` | text | Not marked | — |
| Burial date | `burialDate` | date | Not marked | — |
| Remarks | `remarks` | textarea | Not marked | — |


Displayed table columns: **Certificate**, **Actions**.


### Actions


| Control | Result | Component |
| --- | --- | --- |
| Add record | Opens a blank creation form. | `register-table.tsx` |
| Print / Save Certificate | Updates local UI state; persistence is described separately below. | `register-table.tsx` |
| Issue | Submits the associated API change; follow the sequence and failure rules below. | `register-table.tsx` |
| Remove | Submits the associated API change; follow the sequence and failure rules below. | `register-table.tsx` |
| Cancel | Invokes the associated handler; see the sequence below. | `register-form-dialog.tsx` |
| Save Changes / Add Record | Submits the associated API change; follow the sequence and failure rules below. | `register-form-dialog.tsx` |
| Print / Save PDF | Opens the browser print dialog; Save as PDF uses the browser destination. | `printable-certificate.tsx` |



### Interaction sequence

Add record → fill the fields below → submit → close and refresh. Edit pre-fills stored values. Remove opens a confirmation and deletes the selected record. Issue certificate saves a certificate number; Print / Save Certificate then opens a printable preview.

### States and rules

The route initially loads 100 records without list pagination controls. Empty and permission-denied states are explicit. Required flags are displayed, but the form uses noValidate and leaves final validation to the API; do not promise native browser validation.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Add record → താഴെയുള്ള ഫീൽഡുകൾ നൽകുക → സമർപ്പിക്കുക → അടച്ച് പുതുക്കും. Edit നിലവിലെ മൂല്യങ്ങൾ നൽകും. Remove സ്ഥിരീകരിച്ച ശേഷം രേഖ നീക്കും. Issue certificate certificate number സംരക്ഷിക്കും; തുടർന്ന് Print / Save Certificate printable preview തുറക്കും.

### നിലകളും നിയമങ്ങളും

ആദ്യം 100 രേഖകൾ വായിക്കുന്നു; പട്ടികയ്ക്ക് പേജ് നിയന്ത്രണങ്ങളില്ല. ശൂന്യ/അനുമതിയില്ലാത്ത നിലകൾ വ്യക്തമാണ്. നിർബന്ധ ചിഹ്നങ്ങളുണ്ടെങ്കിലും form noValidate ഉപയോഗിക്കുന്നു; അവസാന പരിശോധന APIയിലാണ്, browser validation ഉറപ്പാക്കരുത്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
