## Finance settings

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/settings/finance`

### Purpose and access

Configure the operational funds, ledger mappings, numbering, bank accounts, categories, dynamic collection fields, and payment methods used by finance screens.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The screen provides operational funds and COA ledgers, general currency/receipt/voucher settings, bank accounts, collection/expense categories, and payment methods. Category dialogs expose target scope, economic category, amounts, recurrence, and custom fields where applicable.

### Fields and displayed information


Displayed table columns: **Fund Name**, **Code**, **Description**, **Linked Categories**, **Default / Status**, **Actions**, **Ledger Account Name**, **Account Type**, **Mapped Categories**, **Balance**, **Bank Name**, **Account Name**, **Account Number**, **IFSC Code**, **Branch**, **Status**.

### Interaction sequence

Create operational funds and ledger accounts → create a category and map its fund/COA account → configure targets and dynamic fields → save. Set bank accounts and payment methods → save numbering/currency settings → use Collections or Payments with these definitions.

### States and rules

Operational funds and ledger accounts are distinct records. Category COA mapping determines posting; do not treat a saved collection as automatically posted. Each dialog saves independently. Bank editing can keep the existing number when left blank.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Operational funds, ledger accounts സൃഷ്ടിക്കുക → വിഭാഗം സൃഷ്ടിച്ച് fund/COA ബന്ധിപ്പിക്കുക → targets, dynamic fields ക്രമീകരിക്കുക → സംരക്ഷിക്കുക. ബാങ്കുകളും payment methodsഉം നൽകുക → numbering/currency സംരക്ഷിക്കുക → Collections/Paymentsൽ ഉപയോഗിക്കുക.

### നിലകളും നിയമങ്ങളും

Operational fundഉം ledger accountഉം വ്യത്യസ്ത രേഖകളാണ്. COA mapping posting നിർണ്ണയിക്കുന്നു; സംരക്ഷിച്ച എല്ലാ വരവും posted ആണെന്ന് കരുതരുത്. ഓരോ ഡയലോഗും പ്രത്യേകം സംരക്ഷിക്കുന്നു. ബാങ്ക് തിരുത്തലിൽ നമ്പർ ശൂന്യമാക്കിയാൽ നിലവിലെത് നിലനിർത്താം.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
