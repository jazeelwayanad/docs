## Financial years

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/accountant/financial-year`

### Purpose and access

Manage accounting periods and their current/open/closed status.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The table provides Add Financial Year, Set Current, Close FY, and Reopen. The creation dialog asks for name, start date, and end date.

### Fields and displayed information


Displayed table columns: **Year Title**, **Start Date**, **End Date**, **Status**, **Active**, **Actions**.

#### Fields and filters: Financial year client

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Financial Year Name | `name` | text | Yes | e.g. FY 2027-28 |
| Start Date | `startDate` | date | Yes | — |
| End Date | `endDate` | date | Yes | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Add Financial Year | Opens the `modal` view. | `financial-year-client.tsx` |
| Set Current | Submits the associated API change; follow the sequence and failure rules below. | `financial-year-client.tsx` |
| Close FY | Submits the associated API change; follow the sequence and failure rules below. | `financial-year-client.tsx` |
| Reopen | Submits the associated API change; follow the sequence and failure rules below. | `financial-year-client.tsx` |
| Cancel | Closes or clears the `modal` view/selection. | `financial-year-client.tsx` |
| Creating... / Create Financial Year | Submits the associated API change; follow the sequence and failure rules below. | `financial-year-client.tsx` |



### Interaction sequence

Add Financial Year → fill all three fields → submit → refresh. Use Set Current, Close FY, or Reopen on a saved year to call the corresponding backend action.

### States and rules

The client checks that required values exist and sends dates as ISO values. Backend validation governs invalid or overlapping periods; the UI does not establish that every close action succeeds.

## Financial years

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/accountant/financial-year`

### ഉദ്ദേശ്യവും പ്രവേശനവും

അക്കൗണ്ടിംഗ് കാലയളവുകളും current/open/closed നിലയും പരിപാലിക്കുക.

Account sessionഉം തിരഞ്ഞെടുത്ത മഹല്ലിൽ resolved membership contextഉം വേണം; APIയിലെ നിലവിലെ platform elevation pathഉം ഇതിൽപ്പെടും. ഓരോ പ്രവർത്തനത്തിന്റെയും permissions/features API പ്രത്യേകം പരിശോധിക്കുന്നു.

### സ്ക്രീൻ ക്രമം

Add Financial Year, Set Current, Close FY, Reopen എന്നിവ പട്ടികയിലുണ്ട്. സൃഷ്ടിക്കൽ ഡയലോഗിൽ പേര്, ആരംഭതീയതി, അവസാനതീയതി നൽകണം.

### ഫീൽഡുകളും പ്രദർശിപ്പിക്കുന്ന വിവരങ്ങളും

### പ്രവർത്തനക്രമം

Add Financial Year → മൂന്നു ഫീൽഡുകളും നൽകുക → സമർപ്പിക്കുക → പുതുക്കും. സംരക്ഷിച്ച വർഷത്തിൽ Set Current, Close FY, Reopen ഉപയോഗിച്ചാൽ ബന്ധപ്പെട്ട backend പ്രവർത്തനം നടക്കും.

### നിലകളും നിയമങ്ങളും

നിർബന്ധ വിവരങ്ങൾ ഉണ്ടോ എന്ന് client പരിശോധിച്ച് ISO തീയതികൾ അയക്കുന്നു. തെറ്റായതോ തമ്മിൽ മുട്ടുന്നതോ ആയ കാലയളവുകൾ backend പരിശോധിക്കും; എല്ലാ close പ്രവർത്തനവും വിജയിക്കുമെന്ന് UI ഉറപ്പാക്കുന്നില്ല.
