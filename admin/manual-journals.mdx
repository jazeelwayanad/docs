## Manual journals

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/accountant/manual-journals`

### Purpose and access

Review journal postings and create manual double-entry vouchers.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The page lists journal entries and opens a dialog with date, reference, description, and account/debit/credit lines. Add Line expands the journal; at least two UI lines remain.

### Fields and displayed information


Displayed table columns: **Entry #**, **Date**, **Particulars**, **Source**, **Debit**, **Credit**, **Status**.

#### Fields and filters: Journal client

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Date | `date` | date | Yes | — |
| Reference / Cheque # | `reference` | text | Not marked | e.g. JV-001 |
| Narration / Description | `description` | text | Yes | Description of journal entry... |
| Line.account id | `line.accountId` | select | Yes | — |
| Line.debit | `line.debit` | number | Not marked | Debit (₹) |
| Line.credit | `line.credit` | number | Not marked | Credit (₹) |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| New Journal Entry | Opens the `modal` view. | `journal-client.tsx` |
| + Add Line | Updates local UI state; persistence is described separately below. | `journal-client.tsx` |
| Cancel | Closes or clears the `modal` view/selection. | `journal-client.tsx` |
| Posting... / Post Entry | Submits the associated API change; follow the sequence and failure rules below. | `journal-client.tsx` |



### Interaction sequence

New Journal Entry → select accounts and enter debit/credit values → add lines if needed → balance total debits and credits → submit → refresh the journal list.

### States and rules

Unbalanced entries are rejected before posting. Zero-amount lines are omitted from the submitted payload. Account choices come from the tenant’s chart of accounts.

Paths below are relative to the application repository. This is source-reviewed behavior, not a recorded browser test.

- `apps/web/src/app/sites/admin/[tenant]/accountant/manual-journals/page.tsx`

Relevant controller permission keys: `accounting.accounts.manage`, `accounting.journal.create`, `accounting.view`, `accounting.journal.cancel`, `accounting.ledger.view`, `accounting.reports.view`. Keys are operation-specific; the current guard grants OWNER/ADMIN and its platform-elevation context an operational bypass. A visible control still does not establish authorization.

## Manual journals

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/accountant/manual-journals`

### ഉദ്ദേശ്യവും പ്രവേശനവും

Journal postings പരിശോധിച്ച് manual double-entry വൗച്ചറുകൾ സൃഷ്ടിക്കുക.

Account sessionഉം തിരഞ്ഞെടുത്ത മഹല്ലിൽ resolved membership contextഉം വേണം; APIയിലെ നിലവിലെ platform elevation pathഉം ഇതിൽപ്പെടും. ഓരോ പ്രവർത്തനത്തിന്റെയും permissions/features API പ്രത്യേകം പരിശോധിക്കുന്നു.

### സ്ക്രീൻ ക്രമം

Journal പട്ടികയും തീയതി, reference, വിവരണം, account/debit/credit വരികളുള്ള ഡയലോഗും ഉണ്ട്. Add Line പുതിയ വരി ചേർക്കും; UIയിൽ കുറഞ്ഞത് രണ്ടു വരികൾ നിലനിൽക്കും.

### പ്രവർത്തനക്രമം

New Journal Entry → അക്കൗണ്ടുകളും debit/credit തുകയും നൽകുക → ആവശ്യമെങ്കിൽ വരികൾ ചേർക്കുക → ആകെ debit, credit തുല്യമാക്കുക → സമർപ്പിക്കുക → പട്ടിക പുതുക്കും.

### നിലകളും നിയമങ്ങളും

തുല്യമല്ലാത്ത entry സമർപ്പിക്കുന്നതിന് മുമ്പ് നിരസിക്കുന്നു. പൂജ്യം തുകയുള്ള വരികൾ payloadൽ ഉൾപ്പെടില്ല. മഹല്ലിന്റെ chart of accountsൽ നിന്നാണ് അക്കൗണ്ടുകൾ തിരഞ്ഞെടുക്കുന്നത്.
