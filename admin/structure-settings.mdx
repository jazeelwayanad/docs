## Structure settings

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/settings/structure`

### Purpose and access

Configure subdivisions, house numbering, and family categories.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

Organization contains a divisions toggle, preferred division term, numbering method, and prefix. Division rows have order/edit/activation controls. Family categories have their own toggle, term, list, and save controls.

### Interaction sequence

Enable divisions → choose terminology and numbering → Save. Add/edit subdivision definitions separately; move rows to save their order. Enable family categories → set their term → Save → maintain category definitions.

### States and rules

Settings and list records save through separate API requests. With divisions disabled numbering is GLOBAL. Prefixes are normalized to uppercase. Permission-denied and no-definition states are explicit.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### ഉദ്ദേശ്യവും പ്രവേശനവും

### പ്രവർത്തനക്രമം

പ്രദേശങ്ങൾ സജീവമാക്കുക → പേരും നമ്പറിംഗും തിരഞ്ഞെടുക്കുക → Save. പ്രദേശനിർവചനങ്ങൾ പ്രത്യേകം ചേർക്കുക/തിരുത്തുക; വരികളുടെ ക്രമം മാറ്റാം. കുടുംബവിഭാഗങ്ങൾ സജീവമാക്കുക → പേര് നൽകുക → Save → നിർവചനങ്ങൾ പരിപാലിക്കുക.

### നിലകളും നിയമങ്ങളും

Settingsഉം പട്ടിക രേഖകളും വ്യത്യസ്ത അഭ്യർത്ഥനകളിൽ സംരക്ഷിക്കുന്നു. പ്രദേശങ്ങൾ ഇല്ലെങ്കിൽ numbering GLOBAL ആണ്. Prefix വലിയ അക്ഷരങ്ങളാക്കുന്നു. അനുമതിയില്ലാത്തതും നിർവചനങ്ങളില്ലാത്തതും പ്രത്യേക നിലകളാണ്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
