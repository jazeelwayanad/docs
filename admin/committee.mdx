## Committee office bearers

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/committee`

### Purpose and access

Maintain committee posts and the member assigned to each office.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The roster lists posts and offers Add post, Edit, and Remove. The post dialog captures member, designation, display order, and term start/end dates.

### Fields and displayed information


Displayed table columns: **Designation**, **Member**, **Term**, **Actions**.

#### Fields and filters: Committee post form dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Member | `post-member` | select | Yes | Select a member |
| Designation | `post-designation` | text | Yes | — |
| Display order | `post-order` | number | Not marked | min 0 |
| Term start | `post-term-start` | date | Not marked | — |
| Term end | `post-term-end` | date | Not marked | — |



### Actions

| --- | --- | --- |

### Interaction sequence

Add post → complete the post details → save → refresh. Edit opens the saved post; Remove opens a confirmation before the delete request.

### States and rules

Committee access is permission-gated. An empty roster has its own message. Office-bearer records are distinct from platform roles and tenant administrator permissions.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Add post → വിവരങ്ങൾ നൽകുക → സംരക്ഷിക്കുക → പുതുക്കും. Edit നിലവിലെ സ്ഥാനം തുറക്കും; Remove delete അഭ്യർത്ഥനയ്ക്കു മുമ്പ് സ്ഥിരീകരണം ചോദിക്കും.

### നിലകളും നിയമങ്ങളും

കമ്മിറ്റി പ്രവേശനം അനുമതിയെ ആശ്രയിക്കുന്നു. സ്ഥാനങ്ങളില്ലെങ്കിൽ പ്രത്യേക സന്ദേശമുണ്ട്. സ്ഥാനരേഖകൾ platform role അല്ലെങ്കിൽ tenant administrator അനുമതികളിൽ നിന്ന് വ്യത്യസ്തമാണ്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
