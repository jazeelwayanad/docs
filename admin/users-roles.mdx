## Tenant users

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/settings/admins`

### Purpose and access

Manage user accounts that have administrative membership in this Mahallu.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The page contains the administrator list, role selectors, removal controls, and an Add a user form asking for email and role.

### Fields and displayed information


Displayed table columns: **Name**, **Email**, **Role**.

#### Fields and filters: Admins table

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Admin.role.key | `admin.role.key` | select | Not marked | — |
| Email | `add-admin-email` | email | Yes | person@example.com |
| Role | `add-admin-role` | select | Not marked | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Remove | Selects the record for the removal confirmation dialog. | `admins-table.tsx` |
| Remove | Submits the associated API change; follow the sequence and failure rules below. | `admins-table.tsx` |
| Add | Submits the associated API change; follow the sequence and failure rules below. | `admins-table.tsx` |


#### Linked navigation

| Link | Target in source |
| --- | --- |
| Manage roles → | `/${slug}/settings/admins/roles` |



### Interaction sequence

Enter an existing account email and role → Add → refresh. Change a listed user’s role to update membership; Remove requires confirmation before removing access.

### States and rules

This manages tenant memberships, not citizen member records. Role-rank and permission checks are enforced by the API. A denied administrators view shows a permission panel.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

## Tenant roles

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/settings/admins/roles`

### Purpose and access

Define tenant-specific roles and their permission sets.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The role table provides Create role, Edit, Duplicate, Deactivate, and Reactivate. The dialog exposes role identity and permission selection.

### Fields and displayed information


Displayed table columns: **Role**, **Type**, **Permissions**, **Members**, **Status**, **Actions**.

#### Fields and filters: Role form dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Role name | `role-name` | text | Yes | — |
| Description | `role-description` | textarea | Not marked | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Create role | Invokes the associated handler; see the sequence below. | `roles-table.tsx` |
| Duplicate | Submits the associated API change; follow the sequence and failure rules below. | `roles-table.tsx` |
| Deactivate | Selects the record for `deactivate target`. | `roles-table.tsx` |
| Reactivate | Submits the associated API change; follow the sequence and failure rules below. | `roles-table.tsx` |
| Deactivate | Submits the associated API change; follow the sequence and failure rules below. | `roles-table.tsx` |
| Cancel | Invokes the associated handler; see the sequence below. | `role-form-dialog.tsx` |
| Save Changes / Create role | Submits the associated API change; follow the sequence and failure rules below. | `role-form-dialog.tsx` |


#### Linked navigation

| Link | Target in source |
| --- | --- |
| ← Users | `/${slug}/settings/admins` |



### Interaction sequence

Create or edit a role → choose its permissions → save and refresh. Duplicate creates another role; Deactivate/Reactivate changes availability through distinct API operations.

### States and rules

Built-in/system role restrictions and escalation checks belong to the backend. Deactivating a role is distinct from deleting a user or removing a member record.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.
