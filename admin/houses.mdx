## Houses directory

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/houses`

### Purpose and access

Maintain physical dwellings separately from the families and members linked to them.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The directory has Add house, search by number/name/address, division and active-status filters, and house rows with edit and activation actions. The dialog contains display number, name, division, address, and notes.

### Fields and displayed information


Displayed table columns: **House**, **Division**, **Address**, **Status**, **Actions**.

#### Fields and filters: Houses registry

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Query | `query` | text | Not marked | Search house number, name, address… |
| Division filter | `divisionFilter` | select | Not marked | All divisions |
| Status filter | `statusFilter` | select | Not marked | Active, Inactive, All; Initial: active |


#### Fields and filters: House form dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |

| House name | `house-name` | text | Not marked | — |
| Division | `house-division` | select | Not marked | No division |

| Notes | `house-notes` | textarea | Not marked | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Add house | Opens a blank creation form. | `houses-registry.tsx` |
| Deactivate / Reactivate | Submits the associated API change; follow the sequence and failure rules below. | `houses-registry.tsx` |
| Cancel | Invokes the associated handler; see the sequence below. | `house-form-dialog.tsx` |
| Save Changes / Add House | Submits the associated API change; follow the sequence and failure rules below. | `house-form-dialog.tsx` |



### Interaction sequence

Add house → enter the required display number → choose a division if applicable → save → the dialog closes and the list refreshes. Open a house for its household information. Row edit updates the record; activation toggles its active status.

### States and rules

The page handles denied houses.view with a permission message. Empty search results are distinct from an empty directory. Add/edit sends API requests and leaves an inline error visible if the request fails.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Add house → നിർബന്ധമായ display number നൽകുക → ആവശ്യമെങ്കിൽ പ്രദേശം തിരഞ്ഞെടുക്കുക → സംരക്ഷിക്കുക → ഡയലോഗ് അടഞ്ഞ് പട്ടിക പുതുക്കും. വീടിന്റെ വിശദാംശങ്ങൾ തുറക്കാം. വരിയിലെ തിരുത്തലും സജീവസ്ഥിതി മാറ്റവും രേഖ പുതുക്കുന്നു.

### നിലകളും നിയമങ്ങളും

houses.view ഇല്ലെങ്കിൽ അനുമതി സന്ദേശം കാണിക്കും. തിരച്ചിലിൽ ഫലമില്ലാത്തതും വീടുകളില്ലാത്തതും വേർതിരിക്കുന്നു. ചേർക്കൽ/തിരുത്തൽ API അഭ്യർത്ഥനകളാണ്; പരാജയപ്പെട്ടാൽ ഡയലോഗിൽ പിശക് കാണിക്കും.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
