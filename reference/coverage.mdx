## Review notes

- Family bulk house assignment and removal only show success; they make no persistence request. [Specification](/family).
- Member bulk deletion suppresses per-record failures; reported success can exceed deleted records. [Specification](/members).
- Family intake makes sequential requests; later errors can leave a house/family or some members saved. [Specification](/family).
- Website branding, password, visibility, and domain changes are local state; analytics is an empty presentation. [Specification](/general).
- Tenant billing plans, usage, and payment presentation use fixed/display data; control billing operations are API-backed. [Specification](/overview-2).
- Dedicated report date/basis controls are not passed to their server data loaders; report-catalog entries include approximations/fixed rows. [Specification](/reports-2).
- Member certificate/aid buttons submit no requests. Prayer times and some membership/health badges are fixed text. [Specification](/member/dashboard).
- Website shortcuts and the dues notification point to routes absent from this inventory. [Specification](/reference/shared-navigation).
- The setup entry reads a stored draft; the current wizard does not continuously persist its edits. [Specification](/mahallu-setup).

## Additional source findings

- OTP login uses a server-log development provider; there is no SMS gateway. [Member login](/member/login).
- Member/public feeds call operator-JWT-protected endpoints and can appear empty for member-only or anonymous sessions. [Public home](/member/public-home).
- Collection custom-field required markers are not all checked by the submit handler, and GENERAL/NO_TARGET targeting differs. [Record collection](/admin/record-collection).
- Tenant guards currently elevate platform-membership accounts and bypass permissions for OWNER/ADMIN contexts. [Shared navigation](/reference/shared-navigation).

- Account parent selection sends `parentId`, but DTOs require `parentAccountId`; strict validation rejects the request. [Chart of accounts](/charts-of-accounts).

## Verification boundary

Behavior was traced through route components, rendered dialogs, data helpers, API controllers/DTOs, and relevant guards/services. The route inventory stores source paths and hashes so future source changes can be detected. No authenticated app/browser journey, real SMS, payment, certificate, or destructive operation was executed. The documentation preview is a separate check from application behavior.

Source commit: `0995e04fcebfe19561950bed799c0c70cf5595db`. Local application changes may exist; hashes capture the files actually reviewed.
