## Members directory

Host: `admin.<ROOT_DOMAIN>` · Route: `/[tenant]/members`

### Purpose and access

Maintain individual member records and their family, education, work, health, and residency information.

You need an account session and a resolved membership context in the selected Mahallu (including the API’s current platform elevation path). The API independently checks the requested operation’s permissions and feature availability.

### Screen layout

The directory contains summary/filter pills, search, family and blood-group filters, sorting, a selectable table, page-size controls, and a bulk-action bar. Add/edit opens a four-tab dialog: identity, education, health, and address.

### Interaction sequence

Choose Add member → enter a full name in identity → complete education/work, health, and address tabs → submit → the dialog closes and the directory refreshes. Open a row to inspect its profile. Edit pre-fills existing values; individual deletion requires confirmation.

### States and rules

Full name is required. The server page initially fetches at most 100 members; client filtering and pagination operate on the loaded list. Import Data, Bulk Photos, and ID Cards only show notifications. Bulk deletion suppresses individual failures and can overstate success.

Explicit validation messages in the rendered forms:

- Member full name is required.


The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Add member തിരഞ്ഞെടുക്കുക → identityയിൽ മുഴുവൻ പേര് നൽകുക → വിദ്യാഭ്യാസം/ജോലി, ആരോഗ്യം, വിലാസം പൂർത്തിയാക്കുക → സമർപ്പിക്കുക → ഡയലോഗ് അടയുകയും പട്ടിക പുതുക്കുകയും ചെയ്യും. വരി തുറന്ന് പ്രൊഫൈൽ കാണാം. തിരുത്തലിൽ നിലവിലെ വിവരങ്ങൾ വരും; വ്യക്തിഗത നീക്കലിന് സ്ഥിരീകരണം വേണം.

### നിലകളും നിയമങ്ങളും

മുഴുവൻ പേര് നിർബന്ധമാണ്. ആദ്യം പരമാവധി 100 അംഗങ്ങളെയാണ് വായിക്കുന്നത്; ഫിൽട്ടറും പേജിംഗും ഈ ലിസ്റ്റിലാണ് പ്രവർത്തിക്കുന്നത്. Import Data, Bulk Photos, ID Cards അറിയിപ്പുകൾ മാത്രം കാണിക്കുന്നു. കൂട്ട നീക്കലിൽ ഓരോ പരാജയവും മറയ്ക്കുന്നതിനാൽ വിജയസംഖ്യ തെറ്റാകാം.

Rendered formsലെ വ്യക്തമായ validation സന്ദേശങ്ങൾ:

- Member full name is required.


Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
