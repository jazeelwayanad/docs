## Tenant command center

Host: `control.<ROOT_DOMAIN>` · Route: `/tenants/[tenantId]`

### Purpose and access

Inspect and administer one tenant’s identity, features, operations, subscription, invoices, payments, and audit history.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

TenantCommandCenter provides tabbed sections for Mahalle Profile, Masjid/religious leadership, jurisdiction, office bearers, module overrides, subscription, invoices, payments, and audit. It also opens public/admin sites and tenant operations views.

### Interaction sequence

Select a tenant → choose a tab → Edit profile or change a feature override → save and refresh. Use billing tools to assign plans, issue invoices, or record payments. Suspend/reactivate toggles tenant status; permanent delete requires the confirmation slug.

### States and rules

Feature overrides offer Inherit, Force on, Force off. Missing tenants use notFound. Opening the admin site does not itself create a support session or impersonate a tenant administrator; backend permission rules still apply.

Explicit validation messages in the rendered forms:

- Mahalle name cannot be empty


The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.
