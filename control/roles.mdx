## Platform roles

Host: `control.<ROOT_DOMAIN>` · Route: `/roles`

### Purpose and access

Inspect platform-level permissions and assign or revoke platform access.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

Platform Roles & Permissions shows role summaries and staff assignments. Assign Platform Role asks for a user and SUPER_ADMIN, PLATFORM_STAFF, or PLATFORM_SUPPORT.

### Fields and displayed information


Displayed table columns: **Permission**, **Identifier Key**, **SUPER_ADMIN**, **PLATFORM_STAFF**, **PLATFORM_SUPPORT**, **Operator**, **Contact Email**, **Phone**, **Account Status**, **Action**.

#### Fields and filters: Roles permissions view

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Select User | `assign-user-select` | select | Yes | Choose a user... |
| Platform Role | `assign-role-select` | select | Yes | SUPER_ADMIN (Full Root Privileges), PLATFORM_STAFF (Operations & Billing), PLATFORM_SUPPORT (Support Mode Only); Initial: PLATFORM_STAFF |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Assign Role | Opens the `is assign` view. | `roles-permissions-view.tsx` |
| Revoke platform role | Submits the associated API change; follow the sequence and failure rules below. | `roles-permissions-view.tsx` |
| Cancel | Closes or clears the `is assign` view/selection. | `roles-permissions-view.tsx` |
| Grant Platform Access | Submits the associated API change; follow the sequence and failure rules below. | `roles-permissions-view.tsx` |



### Interaction sequence

Assign Role → choose account and role → Grant Platform Access → refresh. Revoke sends role=null for the selected account.

### States and rules

These roles apply across the control plane and do not replace tenant roles. The API restricts grant/revoke operations; the role summary is descriptive rather than an editable permission matrix.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Assign Role → account/role → Grant Platform Access → പുതുക്കും. Revoke തിരഞ്ഞെടുത്ത accountന് role=null അയക്കും.

### നിലകളും നിയമങ്ങളും

ഇവ control plane roles ആണ്; tenant rolesന് പകരമല്ല. Grant/revoke API നിയന്ത്രിക്കുന്നു; role summary വിവരണമാണ്, editable permission matrix അല്ല.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
