## Tenant billing operations

Host: `control.<ROOT_DOMAIN>` · Route: `/tenants/[tenantId]/billing`

### Purpose and access

Manage the persisted subscription, invoices, and payment records for one tenant.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

The screen groups Subscription, Invoices, and Payments. Subscription selects a plan and status. Invoice creation asks amount, description, and due date; payment recording asks amount, method, and reference.

### Interaction sequence

Assign plan or change status → refresh. Issue invoice → enter amount/details → save. Mark paid or Void operates on an invoice. Record payment creates a separate payment record.

### States and rules

Display amounts are converted to minor units before posting. Invoice status changes and payment recording are distinct API calls; do not assume recording a payment automatically settles an invoice. This is separate from the tenant’s static billing UI.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

### പ്രവർത്തനക്രമം

Plan നൽകുകയോ status മാറ്റുകയോ ചെയ്യുക → പുതുക്കും. Issue invoice → തുക/വിവരങ്ങൾ → സംരക്ഷിക്കുക. Mark paid/Void invoice മാറ്റും. Record payment പ്രത്യേകം payment record സൃഷ്ടിക്കും.

### നിലകളും നിയമങ്ങളും

തുക minor units ആക്കി അയക്കുന്നു. Invoice status മാറ്റവും payment recordഉം വ്യത്യസ്ത API calls ആണ്; payment ചേർത്താൽ invoice സ്വയം settle ആകുമെന്ന് കരുതരുത്. Tenantന്റെ static billing UIയിൽ നിന്ന് ഇത് വേറെയാണ്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
