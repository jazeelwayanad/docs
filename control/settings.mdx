## System settings

Host: `control.<ROOT_DOMAIN>` · Route: `/settings`

### Purpose and access

Edit platform configuration and inspect system telemetry.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

General Platform Identity covers name, root domain, support email, currency, and timezone. Security & Session Policies covers timeout/session count. Fleet & Onboarding Defaults covers trial/audit defaults; telemetry and fleet/compliance panels are read-only.

### Actions


| Control | Result | Component |
| --- | --- | --- |
| Save Changes | Submits the associated API change; follow the sequence and failure rules below. | `platform-settings-view.tsx` |



### Interaction sequence

Change configuration → Save Changes → patch /platform/settings → refresh. Inspect telemetry separately from the editable fields.

### States and rules

Persisted setting values do not prove every runtime service consumes them. Document the saving operation without claiming that editing rootDomain automatically rewrites DNS or that all policy controls are fully enforced.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

| നിയന്ത്രണം | ഫലം | Component |

### പ്രവർത്തനക്രമം

ക്രമീകരണം മാറ്റുക → Save Changes → /platform/settings patch → പുതുക്കും. Telemetry editable fieldsൽ നിന്ന് വേർതിരിച്ച് പരിശോധിക്കുക.

### നിലകളും നിയമങ്ങളും

Setting സംരക്ഷിച്ചുവെന്നത് എല്ലാ runtime serviceഉം ഉപയോഗിക്കുന്നു എന്ന തെളിവല്ല. RootDomain തിരുത്തിയാൽ DNS മാറുമെന്നോ എല്ലാ policiesഉം നടപ്പിലാകുമെന്നോ അവകാശപ്പെടരുത്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
