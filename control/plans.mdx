## Plans and entitlements

Host: `control.<ROOT_DOMAIN>` · Route: `/plans`

### Purpose and access

Maintain platform subscription plans and their included features.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

The plans table offers New plan, Features, and Remove. Creation fields are name, key, price, and monthly/yearly billing period. Features opens an entitlement selection dialog.

### Fields and displayed information


Displayed table columns: **Name**, **Key**, **Price**, **Limits**, **Features**, **Subscribers**.

#### Fields and filters: Create plan dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Name | `plan-name` | text | Yes | Growth |
| Key | `plan-key` | text | Yes | growth |
| Price (leave blank for custom/contact-us pricing) | `plan-price` | number | Not marked | 999.00; min 0 |
| Billing period | `plan-period` | select | Not marked | Monthly, Yearly; Initial: MONTHLY |


#### Fields and filters: Plan features dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Selected.has(feature.id) | `selected.has(feature.id)` | checkbox | Not marked | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| Remove | Opens the `open` view. | `plans-table.tsx` |
| Remove | Submits the associated API change; follow the sequence and failure rules below. | `plans-table.tsx` |
| New plan | Opens the `create` view. | `plans-table.tsx` |
| Features | Updates local UI state; persistence is described separately below. | `plans-table.tsx` |
| Create plan | Submits the associated API change; follow the sequence and failure rules below. | `create-plan-dialog.tsx` |
| Save entitlements | Submits the associated API change; follow the sequence and failure rules below. | `plan-features-dialog.tsx` |



### Interaction sequence

New plan → enter details → create → refresh. Features → choose included feature IDs → Save entitlements → refresh. Remove requires confirmation.

### States and rules

Entered prices are converted to minor units. Feature entitlements govern effective tenant availability along with overrides; displayed plan entries are persisted records here.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

## Plans and entitlements

Host: `control.<ROOT_DOMAIN>` · Route: `/plans`

### ഉദ്ദേശ്യവും പ്രവേശനവും

Platform subscription plans, ഉൾപ്പെടുന്ന features എന്നിവ പരിപാലിക്കുക.

Account sessionഉം platform accessഉം വേണം. Platform privileges tenant rolesൽ നിന്ന് വേറെയാണ്; privileged writes endpoint role checksന് വിധേയമാണ്.

### സ്ക്രീൻ ക്രമം

പട്ടികയിൽ New plan, Features, Remove ഉണ്ട്. Name, key, price, monthly/yearly period നൽകാം. Features entitlement selection തുറക്കും.

### പ്രവർത്തനക്രമം

New plan → വിവരങ്ങൾ → create → പുതുക്കും. Features → feature IDs തിരഞ്ഞെടുക്കുക → Save entitlements → പുതുക്കും. Removeന് സ്ഥിരീകരണം വേണം.

### നിലകളും നിയമങ്ങളും

വില minor units ആക്കുന്നു. Entitlementsഉം overridesഉം ചേർന്ന് tenant ലഭ്യത നിർണ്ണയിക്കുന്നു; ഇവിടെ planകൾ സംരക്ഷിച്ച രേഖകളാണ്.

Rendered action controls pending state അനുസരിച്ച് loading indicator കാണിക്കുന്നു. API save പരാജയപ്പെട്ടാൽ ബന്ധപ്പെട്ട error/notification കാണിക്കും; loading indicator മാത്രം persistence തെളിയിക്കുന്നില്ല.
