## Form templates

Host: `control.<ROOT_DOMAIN>` · Route: `/forms`

### Purpose and access

Create platform-managed form templates.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

Form Templates lists forms and New form. Creation asks name, key, category, and whether the form is platform-wide.

### Fields and displayed information


Displayed table columns: **Name**, **Key**, **Category**, **Version**, **Assignment**.

#### Fields and filters: Create form dialog

| Field / control | Reference | Input | Required marker | Choices / hints / initial values |
| --- | --- | --- | --- | --- |
| Name | `form-name` | text | Yes | Marriage NOC Request |
| Key | `form-key` | text | Yes | marriage-noc |
| Category (optional) | `form-category` | text | Not marked | Certificates |
| Is platform wide | `isPlatformWide` | checkbox | Not marked | — |



### Actions


| Control | Result | Component |
| --- | --- | --- |
| New form | Opens the `create` view. | `forms-table.tsx` |
| Create form | Submits the associated API change; follow the sequence and failure rules below. | `create-form-dialog.tsx` |


#### Linked navigation

| Link | Target in source |
| --- | --- |
| Open | `/forms/${form.id}` |



### Interaction sequence

New form → enter identity/category and assignment scope → Create form → navigate to /forms/{templateId} to define version fields.

### States and rules

The forms route exists but is absent from the current control sidebar; document it as a direct route. Creating a template does not publish its fields or complete member self-service integration.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.

## Form template detail

Host: `control.<ROOT_DOMAIN>` · Route: `/forms/[templateId]`

### Purpose and access

Maintain form versions, fields, publication, and tenant assignment.

You need an account session and platform access. Platform privileges are separate from tenant roles; privileged writes remain subject to endpoint role checks.

### Screen layout

The detail view has version history, draft-field editing, Publish/Open new draft version controls, Assignment, and Delete form. Fields specify identity, type, options, required status, description, and order.

### Fields and displayed information


Displayed table columns: **Order**, **Label**, **Key**, **Type**, **Required**.

### Interaction sequence

Open a draft → add/edit fields → Publish with confirmation → create a new draft for subsequent changes. Choose platform-wide or selected tenants → Save assignment. Delete form returns to /forms.

### States and rules

Published and draft versions are distinct. Template editing and tenant assignment save independently; published forms are not automatically wired to the placeholder request buttons in the member dashboard.

The rendered action controls bind loading indicators to pending state. Failed API saves keep their documented error/notification path; a loading indicator alone does not establish persistence.
